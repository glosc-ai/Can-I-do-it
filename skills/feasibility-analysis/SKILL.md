# 项目可行性分析 Skill

## 工作方式

先读取用户上传的文件（PDF、DOCX、TXT/Markdown 或图片），把事实和推测分开。只对文件或外部研究中有依据的结论给高置信度；缺失的数据必须列为待验证问题，不能用行业常识补齐。

## 调查维度与权重

| key            | 维度           | 权重 | 重点调查                                   |
| -------------- | -------------- | ---: | ------------------------------------------ |
| problem        | 问题与需求     |   15 | 痛点频率、付费意愿、目标用户、需求证据     |
| market         | 市场空间       |   15 | TAM/SAM/SOM、增长、区域、进入时机          |
| solution       | 解决方案与技术 |   12 | 产品价值、技术可行性、交付复杂度、知识产权 |
| competition    | 竞争与差异化   |   12 | 替代方案、竞品、壁垒、护城河               |
| business_model | 商业模式与财务 |   15 | 收入、成本、毛利、现金流、盈亏平衡         |
| go_to_market   | 获客与运营     |   10 | 渠道、转化、留存、供应链和交付             |
| legal          | 法规与合规     |    8 | 牌照、隐私、数据、合同和地域限制           |
| team           | 团队与执行     |    8 | 关键能力、资源、里程碑、组织风险           |
| risk           | 风险与验证     |    5 | 关键假设、敏感性、最小验证实验和止损线     |

每个维度输出 `score`（0-100）、`confidence`（0-100）、`reasoning`、`evidence[]`、`gaps[]`。最终分数为各维度 `score × weight` 的加权平均，四舍五入到 1 位小数。

## 建议调查清单

1. **案头研究**：定义目标区域和用户，收集公开市场规模、增长、价格、政策和竞品信息；记录来源、日期和口径。
2. **客户验证**：做 5–10 次目标用户访谈，观察真实工作流，验证痛点频率、替代方案和付费意愿；优先记录原话和行为，不把“听起来不错”当成需求证据。
3. **竞品验证**：用竞品试用、神秘客或公开评价核对功能、价格、渠道、留存和差评，区分直接竞争、替代品和潜在进入者。
4. **技术验证**：针对最高风险做技术 spike 或可交付原型，验证性能、数据、供应链、集成、知识产权和交付周期。
5. **财务验证**：建立单客经济模型（获客成本、转化、客单价、毛利、留存、回本周期），做基准/乐观/悲观三套现金流和敏感性分析。
6. **合规验证**：确认牌照、税务、隐私、数据跨境、内容/行业监管、合同和保险要求，必要时让专业人士复核。
7. **小规模试点**：设定 2–4 周最小验证实验、成功指标、样本量、预算上限、停止线和下一步决策，避免只凭计划书下结论。

证据优先级从高到低：已付费或真实使用行为 > 可复核的一手访谈/试点数据 > 有来源的公开数据 > 团队假设 > 泛化行业常识。没有检索工具时不得编造外部数据，统一写入 `gaps`。

## 分数解释

- 80–100：可行，已有较强证据；给出放大建议和监控指标。
- 60–79：有条件可行；先完成列出的验证实验再投入大额资源。
- 40–59：风险较高；明确需要推翻或重做的假设。
- 0–39：当前不可行；说明决定性缺口和停止条件。

## 输出格式

不要输出隐含思维链或无法验证的内部推理；只记录面向用户可复核的调查摘要、事实依据、计算结果和验证动作。必须返回 JSON，不要 Markdown 代码围栏：

```json
  "overall_score": 0,
  "verdict": "有条件可行",
  "summary": "一句话结论",
  "dimensions": [

      "name": "市场空间",
      "score": 0,
      "weight": 15,
      "confidence": 0,
      "reasoning": "依据与可复核结论",

    }
  ],

    {
      "step": "market",
      "title": "市场空间",

      "summary": "本步如何调查、得出什么结论",
      "questions": ["下一步问题"]
    }
  ],
  "next_actions": ["优先级最高的验证动作"]
}
```
